# Tasks: Blurry & Duplicate Photo Cleanup

**Input**: Design documents from `/specs/001-photo-cleanup/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/services.md,
contracts/ui.md, quickstart.md

**Tests**: Included. The constitution (Principle V) requires automated no-network checks,
contracts/services.md requires a unit test for each guarantee, and the success criteria
SC-002/SC-003 require accuracy tests. Write each story's tests first and confirm they fail.

**Organization**: Tasks are grouped by user story so each story can be built, tested,
and shipped on its own.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on unfinished tasks)
- **[Story]**: Which user story the task belongs to (US1–US6)

## Path Conventions

- `iclean/`: SwiftUI app target (screens and wiring only)
- `Packages/CleanupKit/Sources/CleanupKit/`: all logic (paths are always written in full)
- `Packages/CleanupKit/Tests/CleanupKitTests/`: unit and accuracy tests
- `icleanUITests/`: XCUITest flows
- `Fixtures/`: labeled test photos and videos; `scripts/`: dev scripts

## Rules that apply to every task

- No networking APIs anywhere (`URLSession`, `URLRequest`, `NWConnection`, `import
  Network`, `CFNetwork`, `WKWebView`, `SFSafariViewController`, `CloudKit`). Every PhotoKit
  request MUST set `isNetworkAccessAllowed = false`. `scripts/check-no-network.sh` must pass.
- No third-party runtime dependencies. Apple frameworks only.
- Logging uses `os.Logger` with `.private` for identifiers; never log file contents.
- Every new UI element gets the accessibility identifier listed in contracts/ui.md, a
  VoiceOver label, and Dynamic Type support.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: no dependencies.
- **Foundational (Phase 2)**: depends on Setup. BLOCKS all user stories.
- **User Stories (Phases 3–8)**: each depends only on Foundational. They can run in
  parallel or in priority order P1 → P6.
- **Polish (Phase 9)**: after the stories you plan to ship.

### User Story Dependencies

- **US1 (P1)**: Foundational only. Creates `KeeperRules.swift`, `GroupDetailView.swift`,
  `Fixtures/labels.json`, and `scripts/seed-simulator.sh`, which later stories extend.
  If a later story starts before US1, it creates these files itself.
- **US2 (P2)**: Foundational only.
- **US3 (P3)**: Foundational only; extends `KeeperRules.swift` and `GroupDetailView.swift`.
  Its "exclude items already in Duplicates" rule is enforced by `DefaultResultsBuilder`,
  so it works with or without US1.
- **US4 (P4)**, **US6 (P6)**: Foundational only (metadata-only detectors).
- **US5 (P5)**: Foundational only; reuses `KeeperRules.duplicateKeepers` (create it if US1
  is not done). Pro only since 2026-10-18: the free app does not analyze videos, so its
  detector is off unless `ProFeatures.videoAnalysis` is on (see
  specs/004-phased-cleaning/spec.md FR-004a).

### Within Each Story

Tests first (must fail) → fixtures → detector → keeper rules → register detector → UI →
accuracy/UI tests pass.

### Shared files (avoid editing in parallel)

`iclean/App/Detectors.swift`, `Fixtures/labels.json`,
`Packages/CleanupKit/Sources/CleanupKit/Results/KeeperRules.swift`,
`Packages/CleanupKit/Sources/CleanupKit/Analysis/Analyzer.swift`,
